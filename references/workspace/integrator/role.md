# Integrator Workspace 规则

本文件是 `integrator` 角色的业务自定义规则**内核默认版**。业务 workspace 可在本地覆盖此文件以注入特定项目技术栈的本地运行拓扑、端口映射表与凭据指南。与权威源冲突时以后者为准。

## 业务环境与服务配置指针（供项目 workspace 覆盖）
- 本地多服务端口与拓扑矩阵：`docs/integration/topology.md`（如网关 8080、前端 3000、Mock 服务 9000 等标准分配）
- 本地测试账号与凭据说明：`docs/integration/credentials.md`（联调使用的白名单测试账号、免密 Token 注入）
- 本地 Mock 与数据种子配置：`docs/integration/mock-seeds.md`（基础依赖 Docker/Compose 拉起与数据导入指引）

## 核心执行规范与约束

1. **环境依赖与启动顺序**：
   - 依赖项按照先基础存储（DB/Cache）、再后端接口（API/RPC）、最后前端与反向代理（Web/Gateway）的次序拉起；
   - 每一个拉起的后台服务必须使用明确的日志重定向（如 `>> /tmp/dev-<service>.log 2>&1 &`），以便在启动失败时快速定位堆栈。

2. **Readiness 存活探活铁律**：
   - 不以“启动命令返回成功”作为服务可用证据；
   - 必须通过端口轮询（`lsof` / `nc`）或 HTTP 存活接口（`curl -sf`）确认服务已进入 Ready 状态；
   - 探活超过设定阈值（默认 60s）未就绪时，主动抓取末尾日志并终止，避免死等。

3. **真实调用与用例要求**：
   - 必须执行至少一条覆盖本次需求改动的端到端成功链路和一条边界异常链路；
   - 真实捕获响应 JSON 并提取关键字段（如 ID、状态码、分页结构）作为证明；
   - 用例指引必须写清：入口 URL、测试账户、前置条件、操作步骤（1-2-3）、预期页面/接口返回现象。

4. **安全收敛与清理**：
   - 联调任务结束或异常时，执行对应的关闭命令或根据 PID 杀掉拉起的进程；
   - 严禁残留后台孤儿进程霸占系统端口。
